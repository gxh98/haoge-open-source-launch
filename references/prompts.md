## 第一步 · 创建可开源的 Skill

**何时用**：阶段 A，从零生成一个可开源的 Skill 骨架。
**注意**：下面的名称 `make-knowledge-cards` 和功能描述是博主视频里的举例，换成你自己的。

```
Skill Creator

请在当前项目中创建一个可以开源的 Skill:
· Skill 名称: make-knowledge-cards
· 创建位置: skills/make-knowledge-cards
· 功能: 把用户粘贴的文章或本地Markdown/TXT文件转换成5~8张知识卡片
· 每张卡片包含: 标题、核心知识、简明解释、例子或自测问题
· 要求: 提取真正重要的知识; 一张卡片只讲一个知识点; 删除重复内容; 不能编造原文没有的信息; 信息不足时不要强行凑数量
· 暂不支持: 网页抓取、PDF、Anki和图形界面

请使用官方初始化工具创建Skill,完成 SKILL.md 和 agents/openai.yaml,不要添加不必要的脚本。

完成后用不同类型的文章测试,根据结果完善Skill,并运行 quick_validate.py 验证。

在项目根目录创建简洁的 README.md,包含介绍、使用方法和输入输出示例。

先完成本地开发和测试,不要初始化Git,也不要上传GitHub。
```

---

## 第二步 · 完善 README.md

**何时用**：阶段 B，Step 2。

```
请完善项目根目录的README.md,确保包含:

1. 项目解决什么问题
2. 主要功能
3. 安装方法
4. 使用方法
5. 输入输出示例

README 必须与项目真实功能一致。
```

---

## 第三步 · 添加 MIT 许可证

**何时用**：阶段 B，Step 3。

```
请在项目根目录添加 MIT LICENSE。
```

---

## 第四步 · 安全检查

**何时用**：阶段 C，Step 4。**这一步是公开发布的门闸。**

```
请检查整个项目是否存在:
· 密码或 Token
· 个人隐私
· 本地绝对路径
· 临时文件
· 测试垃圾文件
· 不应该公开的内容

先报告检查结果,不要执行Git操作。
```

> 本技能把这一步升级成了可执行脚本：`python scripts/security_scan.py <项目目录>`，
> 会自动分级成 BLOCKER / WARN / INFO，并且输出脱敏。

---

## 第五步 · 安装 Git

**何时用**：阶段 D，Step 5。

```
请检查当前电脑是否安装Git。

如果已经安装,显示版本号。

如果没有安装,请识别当前操作系统,并使用合适的官方方式或系统包管理器安装。

涉及管理员权限、系统弹窗或者安装新的包管理器时,先向我说明并等待确认。

安装完成后再次显示Git版本。
```

---

## 第六步 · 初始化仓库 + 第一次提交

**何时用**：阶段 D，Step 6。

```
请初始化Git 仓库，把默认分支设为main，并准备第一次提交。
```

> 补充：提交前先把 `git status` 给用户看一屏，避免误提交敏感文件。

---

## 第七步 · 安装 GitHub CLI

**何时用**：阶段 E，Step 7。

```
请检查GitHub CLI,也就是gh,是否已经安装。

如果已经安装,显示版本号。

如果没有安装,请根据当前操作系统,使用合适的官方方式或系统包管理器安装。

涉及管理员权限、系统修改或者安装新的包管理器时,先向我说明并等待确认。

安装完成后显示gh版本。
```

---

## 第八步 · 登录 GitHub

**何时用**：阶段 E，Step 8。**授权必须由用户本人完成。**

```
请运行gh auth status,检查GitHub CLI是否已经登录。

如果没有登录,请启动gh auth login:
· 登录 GitHub.com
· 使用 HTTPS
· 通过浏览器登录
· 允许GitHub CLI 为Git配置凭据

需要账号密码、验证码、二次验证或浏览器授权时暂停,让我本人完成。

不要要求我把密码或Token发到对话中。

授权完成后,再次运行gh auth status。
```

---

## 第九步 · 发布

**何时用**：阶段 F，Step 9。**执行前必须先让用户确认。**

```
请准备把当前项目发布到GitHub:

仓库名称: article-to-knowledge-cards
可见性: Public
远程名称: origin
推送分支: main

执行前先让我确认仓库名称、公开范围和即将执行的操作。
```

---

## 第十步 · 版本号

**何时用**：阶段 F，Step 10。

```
请检查当前项目是否适合发布v0.1.0,并准备:

1. v0.1.0 Tag
2. Release 标题
3. 简洁的发布说明
4. 当前功能

创建并推送 v0.1.0 Tag,然后发布GitHub Release。
```
